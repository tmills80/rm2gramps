# `rm2gramps` v2.1 — Citations + Sources

> **For Hermes:** Use the `plan` skill and `test-driven-development` skill to
> implement this plan task-by-task. Each task is one bounded change with a
> failing test first, a green commit second.

**Goal:** add citations and sources to the rm2gramps export. v1
shipped people/events/families/places; v2.1 closes the loop on the
genealogical core (a citation without a parent source is invalid in
Gramps, so the two ship together).

## Why this is its own commit

Grouping rule: commit boundary = "Gramps imports the resulting
`.gramps` without errors." Citations + sources are inseparable on
this rule. Notes / media / repositories are secondary — they each
satisfy the rule independently but the work is small enough to batch
into a separate v2.2 commit.

## Three locked decisions

1. **Slice shape: two commits (v2.1 + v2.2).** This file is v2.1.
2. **Citation narrowing:** emit only citations referenced by
   exported owners (Person / Family / Source / Event). When
   `--person-ids` is supplied, the citation set is bounded to those
   referenced by the selected persons' families/events/sources.
   When exporting the whole DB, every citation is exported. No
   dangling citations nobody asked for.
3. **Unknown `OwnerType` in `CitationLinkTable`:** warn-and-skip.
   Surface a count to stderr via the existing CLI logging; do not
   fail. Documented limitation — values 7 and 19 are seen in
   `SampleTree.rmtree` but are RM-internal extensions whose
   target owner is not enumerable from the link row alone.

## Schema reference

`tools/rmread/docs/rm11-schema.md` § "Citation, source,
multimedia, address, URL".

Key facts from the schema doc:
- `CitationTable.CitationName` is `COLLATE RMNOCASE` — reads work
  thanks to the collation registered in commit `dbb8011`.
- `CitationLinkTable.OwnerType` distribution in `SampleTree.rmtree`:
  `0` (Person) 17, `1` (Family) 48, `2` (Source) 604, `7` 24,
  `19` 9. We handle 0/1/2; warn-and-skip 7/19/anything-else.
- `CitationTable.Fields` and `SourceTable.Fields` are BLOBs (RM
  template-filled field values); v2.1 ignores them — they're
  RM-internal serialisation, not portable to Gramps. We rely on the
  pre-rendered `Footnote` / `ShortFootnote` / `Bibliography` /
  `ActualText` columns instead.
- `SourceTemplateTable` is the *template definition* RM uses for
  sources. Gramps XML has no direct equivalent; v2.1 skips the
  template table. The `<source>` element's `sformat` / `stitle`
  attributes come from `SourceTable.Name`.

## Output shape (Gramps 1.7.2)

```xml
<source handle="_g_s5" change="<ts>" id="S0001">
  <stitle>Births &amp; Baptisms 1840</stitle>
  <sauthor>Staines St Mary</sauthor>
  <sformat>book</sformat>          <!-- hard-coded; Gramps default -->
</source>

<citation handle="_g_c42" change="<ts>" id="C0042">
  <sourceref hlink="_g_s5"/>
  <confidence>2</confidence>      <!-- hard-coded; medium -->
  <noteref hlink="_g_n1"/>        <!-- if citation has a Note -->
  <dateval val="1840-06-12"/>     <!-- if Source.Date known -->
  <page>entry 7</page>             <!-- from RefNumber or similar -->
</citation>
```

And on existing objects:

```xml
<event handle="_g_e5" change="<ts>" id="E0005">
  <type>Birth</type>
  <dateval val="1840-06-12"/>
  <place hlink="_g_p3"/>
  <citationref hlink="_g_c42"/>     <!-- NEW in v2.1 -->
  <citationref hlink="_g_c43"/>     <!-- multiple citations allowed -->
</event>
```

Same pattern for `<person>`, `<family>`, `<source>`.

`<citationref>` placement: per Gramps convention, citationrefs go
*after* the structural children (type/dateval/place) but *before*
description / noteref. We add them in the renderer layer.

## Architecture

Three new modules + extensions to three existing ones:

```
src/rm2gramps/
    sources.py         new — SourceTable row → <source> renderer
    citations.py       new — CitationTable row → <citation> renderer
    citations_walk.py  new — CitationLinkTable walker (OwnerType→owner-id→citation-id)
    handles.py         extend — source_handle(), citation_handle()
    writer.py          extend — load_sources, load_citations, attach_citationrefs_to_events/people/families/sources
    xml.py             extend — new <sources> + <citations> sections

tests/
    test_sources.py        new
    test_citations.py      new
    test_citations_walk.py new (uses SampleTree.rmtree)
    test_writer.py         extend — round-trip now asserts citation invariants
```

Section order in the top-level document (matches `example.gramps`):
```
<events> <people> <families> <sources> <citations> <places>
```

(Sources before citations because Gramps' DTD requires citations to
reference existing sources.)

## Risks / open decisions

1. **Citation confidence.** Gramps `<confidence>` is 0–5. RM doesn't
   carry a comparable field directly; `CitationLinkTable.Quality`
   is text, not an int. v2.1 hard-codes `<confidence>2</confidence>`
   ("normal" in Gramps terminology). Researcher can adjust in Gramps.
   Documented limitation.

2. **Note linkage on citations.** Some citations have an RM
   `Note` column; v2.1 emits it via `<noteref hlink="_g_n…"/>`
   *only if* notes are present. Notes themselves are deferred to
   v2.2 — but we emit the `noteref` element so when notes land,
   nothing breaks.

3. **SourceTemplates.** Skipped. RM's template system is
   proprietary; Gramps has no direct equivalent. We emit
   `<sformat>book</sformat>` (hard-coded) on every source.

4. **Citation ordering.** Per Gramps convention, multiple
   `<citationref>` elements on one event are ordered by `SortOrder`
   from `CitationLinkTable`. The walker already does this; just
   calling it out.

5. **CitationFields blob.** Ignored. RM's internal serialisation
   of filled template fields is not portable to Gramps XML.
   The pre-rendered text columns (Footnote / ShortFootnote /
   Bibliography / ActualText) are portable and we use them.
