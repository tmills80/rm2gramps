# `rm2gramps` v2.2 — Notes + Media + Repositories

> **For Hermes:** Use the `plan` skill and `test-driven-development` skill to
> implement this plan task-by-task. Each task is one bounded change with a
> failing test first, a green commit second.

**Goal:** add notes, media, and repositories to the rm2gramps export.
Closes out the v2 plan-locked deferred slice. v2.1 already shipped
citations and sources; v2.2 is the second half.

## Why one commit (not three)

Same reasoning as v2.1's "citations + sources together": Gramps
import succeeds when each object type's external references
resolve. Notes can be referenced from many object types
(`<noteref>`), so notes landing in isolation would emit
`<noteref>` elements that resolve to nothing. Media ditto
(`<mediaref>`). Repositories attach to citations via
`<reporef>`, so they need citations to land first (already done).

Grouper rule: ship all three together because cross-references
between them and v2.1 already-landed types work out of the box
only when all three ship together.

The single commit also keeps the architectural pattern consistent:
v2.1 = "the link-table polymorphism I", v2.2 = "the same shape
again for the remaining object types."

| Object | Prefix |
|---|---|

| Media (Gramps "Object") | `O` |
| Repository | `R` |

| Object | Handle |
|---|---|
| Note | `_g_n<NoteID>` |
| Media | `_g_o<MediaID>` |
| Repository | `_g_r<AddressID>` |

## Five locked decisions

1. **Notes from inline columns, not a separate table.** RM has no
   `NoteTable` — notes are stored inline as `Note TEXT` columns on
   Person / Event / Family / Source / Place / Citation. v2.2 emits
   one `<note>` per non-empty inline note (dedup by content +
   owner), with the source `<noteref>` pointing at it. Pure-table
   notes would need RM to add one, which it hasn't.
2. **Media narrowing:** media items referenced by exported owners
   (Person / Source / Citation / Event) are exported. Others are
   not — researchers don't want 200 unattached scans in the
   export.
3. **Repositories from `AddressTable.AddressType=0` only.**
   SampleTree only has 14 `AddressLinkTable` rows under OwnerType=3
   (citation-or-event). v2.2 hard-codes "repositories are address
   rows linked to citations." `AddressType` is ignored — every
   address attached to a citation is a repository by Gramps convention.
5. **Unknown OwnerType handling:** warn-and-skip (same as v2.1).
   `SampleTree` `MediaLinkTable` has buckets 0/2/3/4 and we've
   already seen 7/19 in `CitationLinkTable`. Same discipline.
6. **Media thumbnails:** dropped. The `Thumbnail BLOB` is the
   only portable media-embedding Gramps understands, but BLOBs in
   our XML output would balloon file size 100× and Gramps
   re-extracts thumbnails on import anyway. v2.2 emits
   `<mediaref>` with the source file path; the researcher
   re-attaches media in Gramps via the absolute path / URL.

## Schema reference

`rmread/docs/rm11-schema.md` § "Citation, source,
multimedia, address, URL":

- **Notes:** no separate table. Inline columns on Person
  (`PersonTable.Note`), Event (`EventTable.Note`), Family
  (`FamilyTable.Note`), Source (`SourceTable.Note`), Place
  (`PlaceTable.Note`), Citation (`CitationTable.Comments`).
- **Media:** `MultimediaTable` + `MediaLinkTable`. OwnerType
  distribution in `SampleTree.rmtree`: 0 (Person) 3, 2 (Source) 5,
  3 (likely Citation) 79, 4 (likely Event) 80.
- **Repositories:** `AddressTable` + `AddressLinkTable`. Only
  `OwnerType=3` in `SampleTree` (14 rows, attached to citations).

## Output shape (Gramps 1.7.2)

```xml
<note handle="_g_n1" change="<ts>" id="N0001" type="general">
  <text>Free-form text goes here.</text>
</note>

<object handle="_g_o1" change="<ts>" id="O0001">
  <file src="/path/to/image.jpg" mime="image/jpeg"/>
  <description>Photo of headstone</description>
</object>

<repository handle="_g_r1" change="<ts>" id="R0001">
  <rname>Staines St Mary Parish</rname>
  <raddr><street>Church Road</street><city>Staines</city></raddr>
</repository>
```

Cross-references:
```xml
<person ...>
  ...
  <noteref hlink="_g_n1"/>
  <mediaref hlink="_g_o1"/>
</person>

<citation ...>
  ...
  <reporef hlink="_g_r1"/>
</citation>
```

Section order (Gramps convention, verified against example.gramps):
```
events → people → families → sources → citations → places
       → repositories → media → notes
```

(notes last because they're leaf objects referenced from many
places; media before notes because they're larger blobs and a
researcher skimming the file structure finds the text first.)

## Architecture

Three new renderers + three new loaders + extensions to writer and xml:

```
src/rm2gramps/
    notes.py                new — NoteRecord + render_note_xml
    media.py                new — MediaRecord + render_media_xml
    repositories.py         new — RepositoryRecord + render_repository_xml
    handles.py              extend — note_handle(), media_handle(), repository_handle()
    writer.py               extend — load_notes, load_media, load_repositories, attach <noteref>/<mediaref>/<reporef>
    xml.py                  extend — new <repositories>, <media>, <notes> sections
    citationrefs.py         extend — inject_noterefs_into_*, inject_mediarefs_into_*
                              (same anchor-on-closing-tag pattern)

tests/
    test_notes.py           new
    test_media.py           new
    test_repositories.py    new
    test_writer.py          extend — round-trip now asserts note/media/repo invariants
    test_cli.py             extend — assert --person-ids narrows media + notes
```

### T25. writer.py — load_notes

Inline-note dedup rule: build a `dict[hash(text), note_id]` so the
same text appearing on multiple Person / Event / Family records
becomes one `<note>` with multiple `<noteref>` references. This
matters — RM stores the same multi-line research note copied into
many Person rows.

`load_notes(con, *, referenced_owner_ids_by_type: dict[str, set[int]])`
returns `dict[note_id, NoteRecord]` where `note_id` is a stable
synthesised id. Implementation:
1. Collect every non-empty `Note TEXT` column from Person, Event,
   Family, Source, Place, Citation where the owning record is in
   the export scope.
2. Hash each (sha256 of normalised text) → assign synthetic note
   ids 1..N in first-seen order.
3. Return the dict + a side-dict `{hash → note_id}` for callers
   that need to attach `<noteref>` to owners.

Tests in `tests/test_writer.py`:
- Extend round-trip: every `<noteref>` on Person/Event/Family
  resolves; every `<note>` has at least one `<noteref>` (no
  dangling notes).

## Risks / open decisions

1. **AddressType=0 isn't the right repository filter.** Per the
   schema doc, `AddressLinkTable` only has `OwnerType=3` rows in
   `SampleTree.rmtree` — no `AddressType` filter possible. v2.2
   filters only by "address row is linked to a citation we
   exported." If a real DB uses other OwnerTypes, the walker
   warns-and-skips.
2. **Note text styling.** RM notes can contain HTML-ish markup
   (the cite tool already handles this — see
   `rmcite/src/rmcite/richtext.py`). v2.2 emits only
   `<text>` (no markup). v3 will lift to `<styledtext>` when
   styling demand is real.
3. **Media `MediaType` mapping.** RM uses integer MediaType codes;
   we hard-code 1=image/jpeg, 2=application/pdf, 3=audio/mpeg,
   4=video/mp4 (covers the common cases). Unknown types fall back
   to `application/octet-stream`.
4. **Inline-note dedup uses sha256.** The hash is a stable
   identifier only; collision rate is negligible for text <100KB.
   If two distinct notes have the same bytes, they collapse to
   one `<note>` (researcher edits in Gramps). Documented.
5. **Media file paths.** RM stores paths on the original researcher's
machine. Most will be invalid in the new environment. v2.2 emits
them verbatim; researcher re-links media in Gramps via the
absolute path or URL. Thumbnail BLOBs dropped (Decision 6).
